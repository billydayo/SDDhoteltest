## ⚠️ 這份清單的界線

**只放自動化做不到的事。**

舊清單的教訓是：15 項裡有一半後來被自動化接手，但清單沒有跟著縮短，於是每次
驗收都在重做機器已經做過的事——而真正需要人眼的那幾項反而淹沒在裡面。

因此本清單只收三類：

1. **需要真實外部帳號**（Google OAuth 往返）
2. **需要人眼判斷**（版面、對比、文案是否讀得懂）
3. **需要真實瀏覽器**（console 訊息、Network 面板、檔案下載、重新整理與上一頁）

其餘一律由自動化承擔，並在下方「已由自動化覆蓋」逐條指名是哪一支。
**看到那一節裡的項目時不要重做**——去讀那支測試比手動點一次可靠。

## 前置

### 兩個服務各自啟動

前後端是**兩個獨立的行程**，不再是一個 `index.html`。

```bash
# 終端 1：後端（需 backend/.env，見 backend/README.md）
cd backend && uv run uvicorn sunny.main:app --reload      # http://127.0.0.1:8000

# 終端 2：前端
cd frontend && npm run dev                                 # http://localhost:5173
```

前端以相對路徑 `/api/...` 呼叫後端，由 Vite 的開發代理轉過去。因此**瀏覽器只會
看到 `localhost:5173` 一個來源**——Network 面板裡不該出現 `127.0.0.1:8000`。

### 測試帳號

```
會員   guest@sunny.com / guest123
管理員 admin@sunny.com / admin123
```

### 記錄方式

發現問題時記下五件事：哪一頁、做了什麼、預期什麼、實際看到什麼、console 有無紅字。
少了最後一項，回頭重現的成本會高很多。

## B. 需要人眼：版面與對比

### B1. 響應式（SC-012、T172）

用開發者工具的裝置模擬，在下列寬度逐一看過每一頁：

`320` / `375` / `768` / `1024` / `1440` / `1920`

- [ ] 每個寬度下**頁面本身沒有橫向捲動**（表格與圖表允許在自己的容器內橫捲）
- [ ] 內容不重疊、不被切掉，按鈕不會擠成一團而無法點
- [ ] 房源列表在窄螢幕改為直向堆疊，不是縮小的多欄
- [ ] 首頁滿版主視覺在**有捲軸**的視窗上不產生橫向捲動——`100vw` 含捲軸寬度，
      這是最常見的破口，`styles/index.css` 以 `overflow-x: clip` 擋住
- [ ] 後台表格在窄螢幕可橫捲，且捲動的是**表格自己**，不是整頁

要走過的頁：首頁、房源詳情、訂房三步驟、訂單列表、訂單詳情、退款申請、撰寫評論、
登入、註冊、帳戶設定、我的收藏、客服訊息、服務條款、安全檢測，以及後台十二個模組。

### B2. 對比與色彩（憲章原則 V）

數值部分已由 `frontend/src/styles/contrast.test.ts` 自動重算，**不必手量**。
人眼要看的是那支測試涵蓋不到的：

- [ ] 文字疊在**照片**上的地方仍讀得清楚（首頁主視覺、房源卡片上的標籤）
- [ ] `disabled` 的按鈕看得出是停用的，而不只是「顏色淡一點」
- [ ] 狀態徽章在灰階下仍分得出來（開發者工具 → Rendering → 模擬色覺缺陷）
- [ ] 焦點環在每一種底色上都看得見（深色按鈕上尤其容易消失）

### B3. 文案

- [ ] 錯誤訊息讀得懂，且說得出**下一步該做什麼**，不只說「失敗」
- [ ] 沒有出現開發用語（`null`、`undefined`、`NaN`、`Error:`、英文例外名稱）

## D. 十二個故事的走訪

每一項都是「照著使用者會走的路走一次」，重點在**串起來之後有沒有斷掉**——
單元測試驗的是每一段，這裡驗的是接縫。

- [ ] **US1 瀏覽與搜尋**：從首頁篩選到詳情頁，房態顯示與所選日期一致
- [ ] **US2 註冊與登入**：註冊 → 登入 → 改個人資料 → 登出 → 再登入，資料還在
- [ ] **US3 訂房**：三步驟走完 → 訂單確認頁七項資訊齊全 → 倒數會動
- [ ] **US4 訂單與退款**：在**列表上**直接付款、在**列表上**直接取消
      （二次確認只有一份）、申請退款 → 詳情頁看得到進度
- [ ] **US5 評論**：撰寫評論 → 自動審核結果可解釋 → 通過後出現在房源頁
- [ ] **US6 後台核心**：營運總覽數字合理、房源上下架、訂單查詢、會員列表
- [ ] **US7 後台審核**：評論審核與退款審核各走一次核准與駁回
- [ ] **US8 報表與內容**：改首頁標題與主圖 → 前台立刻反映；報表匯出見 C3
- [ ] **US9 照片品質檢測**：後台上傳房源照片 → 三項指標與總分顯示
- [ ] **US10 收藏**：加入與移除收藏 → 「我的收藏」同步
- [ ] **US11 渠道比價**：預警列表 → 標記已處理
- [ ] **US12 操作日誌與系統參數**：改參數後日誌出現對應紀錄，且**日誌不可編輯**
- [ ] **會員訊息**：會員送出訊息 → 管理員回覆 → 會員只看到「客服人員」，
      看不到管理員姓名（FR-127）
